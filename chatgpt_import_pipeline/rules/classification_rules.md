# V1 分类与候选边界

只用五类：A 工作项目、B AI 学习、C 个人成长、D 运动生活、E 一次性内容。结合标题与可见用户消息；单一关键词或标题不足以证明归类。无法判断时保留 `NEEDS_REVIEW`，不增设第六类。

候选仅是待审线索：知识候选限工作方法、项目经验、可复用流程与决策经验；个人记忆候选限本人明确谈到的人生事件、职业变化、兴趣变化或长期习惯。助手内容、转贴材料、一次性问答不当成用户事实；计划不写成已完成。无法从原话找到方法或影响时留空并标记复核，不编造。对可能含凭据或敏感资料的消息，不摘录正文。

V1.1 候选补充：职业变化只提明确已发生的换部门、转岗、入职、离职等本人陈述；「想、打算、如果、可能」等计划或假设不作为已发生事件。长期项目只提本人明确说正在做且需长期／持续维护的项目；仅出现项目名或让 AI 制作项目文档不算。两者继续保留原话、来源和 `NEEDS_REVIEW`，不新增分类或输出字段。

一张图、临时查询、简单问答通常归 E 且不进入高价值候选。所有候选必须附对话和消息来源。原始数据、Source Layer 与正式库只读。

## V1.2 安全增强（优先于上面的 V1.1 处理方式）

- `claim_status`：FACT=明确自述已发生，CURRENT=明确当前持续，PLAN=意图/计划，HYPOTHESIS=假设/不确定，QUOTE=引用或助手内容，UNKNOWN=依据不足。状态只是规则对陈述形式的判断，不证明陈述真实。整条消息含计划、假设时保守降级；计划、假设与未知仍可保留待审，但不作为个人事实。
- `source_role`：USER_SELF=明确本人陈述，USER_QUOTE=用户贴入/引用，ASSISTANT=原生助手消息，UNKNOWN=不明确。个人记忆必须在消息和事件两层均为 USER_SELF。混合引用与本人表达的消息整体排除；未标注的转贴仍可能无法识别。原生助手消息不参与候选提取。知识候选可保留被标注的引用供审核，不转为个人记忆。
- `candidate_id` / `content_hash`：以候选类型和规范化正文（Unicode NFKC、连续空白归一）生成 SHA-256 标识；记忆同时包含时间，知识使用问题和方法。相同陈述合并 `source_refs`，保留各来源、消息哈希、状态和原文片段；旧 `source` 保留首个来源以兼容。状态冲突变为 UNKNOWN，不自动挑选较强断言。同义改写不合并；相同原话不保证是同一次现实事件，仍需回查时间。
- 新个人记忆的 `impact` 保守留空，避免把同一长消息中其他人的观点或不相关句子附为事件影响；旧版文件不改。
- `import_history.json` 每次在新输出目录最后生成，记录 conversation_id、完整对话 message_hash、主路径逐消息 message_hashes、处理时间、候选文件校验值。指定上一份历史时，未变化对话跳过候选提取；新增/有变化对话重新处理，累计候选按 ID 合并。失败的对话不更新历史；输出未完成时不产生完整历史标记。
- 历史不提供自动更正、撤回或多分支合并：修改陈述后旧证据仍保留待审。连续增量须沿同一份最新完整历史传递；不指定历史按全量运行。
